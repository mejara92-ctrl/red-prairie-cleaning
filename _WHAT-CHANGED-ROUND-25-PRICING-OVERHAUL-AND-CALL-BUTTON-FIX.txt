5. SITE-WIDE FIX: THE "CALL" BUTTON COULD SILENTLY DO NOTHING
--------------------------------------------------------
This is the bug behind "call button is broken." It wasn't broken on
every tap — it was broken specifically when Google's ad-blocked or
slow-loading tracking script didn't get a chance to run, which on a
phone with any ad blocker, content blocker, or slow connection is not
rare.

The old code, on every page's tel: link:
  function gtag_report_conversion(url) {
    var callback = function () { window.location = url; };
    gtag('event', 'conversion', { ..., 'event_callback': callback });
    return false;
  }
`gtag()` is defined locally as a stub that just queues events — it does
nothing by itself. The REAL Google Ads script (loaded from
googletagmanager.com) is what eventually processes that queue and
calls `event_callback`. If that script is blocked, slow, or fails to
load for any reason, `event_callback` is never invoked — and since
`return false` also cancels the link's own default tel: action, tapping
Call just... did nothing. No error, no fallback, no phone call.

Fixed with a 500ms fallback timer that fires the navigation either way,
with a guard so it never double-fires if the real GA callback also
lands:
  function gtag_report_conversion(url) {
    var navigated = false;
    var go = function () { if (navigated) return; navigated = true;
      if (typeof(url) != 'undefined') window.location = url; };
    gtag('event', 'conversion', { ..., 'event_callback': go });
    setTimeout(go, 500);
    return false;
  }
Conversion tracking still fires normally on every call where Google's
script loads in time (the common case) — this only changes what
happens in the failure case, from "nothing" to "the call goes through,
slightly before or after the tracking pixel would have landed."

Applied to every page on the site that has a Call button or a tel:
link using this pattern — the header nav (FAQ / Call / Text us) present
site-wide, plus /book's calendar-screen "Call us" link and every
location/service landing page. 17 files total; each was carrying its
own independent copy of this script (not shared code), so each needed
the same fix individually. All 17 verified with node --check afterward.
