RED PRAIRIE CLEANING — V25 CHANGELOG
/book only. Fixes a real bug on the live site reported by Mike.

1. Add-ons subtext removed
   -------------------------
   Removed "Optional — select any that apply. Tap again to remove." from
   the add-ons screen — it's self-evident from the UI. Restored the
   heading-to-list spacing that line was providing so nothing feels
   cramped without it.

2. Root-caused and fixed: back button broken after resuming a session
   ---------------------------------------------------------------------
   This was a real bug, confirmed and reproduced. When a saved session
   resumed mid-flow (say, step 4 of 8), the boot code replaced the
   page's one and only history entry with just that step — so there
   was nothing underneath it for "back" to go to. Both the on-screen
   Back button and the native back gesture either did nothing or
   bounced the person out of /book entirely, exactly matching "some
   kind of glitch."

   Root cause was specific to the session-resume path added in V22 —
   fresh (non-resumed) sessions and ?service= deep links were never
   affected, and still behave exactly as before.

   Fix: when a session resumes partway through a flow, the boot code
   now rebuilds one history entry per step already passed through
   (service -> bedrooms -> bathrooms -> ... -> wherever they left off),
   instead of collapsing straight to a single entry. Back — on-screen
   or native — now walks back through those steps properly, and
   backing all the way out correctly clears the selected service again,
   matching normal (non-resumed) behavior exactly.

   This directly addresses "people want to go back to try new
   configurations" — going back now reliably lets someone reopen any
   earlier step and change their answer, resumed session or not.
